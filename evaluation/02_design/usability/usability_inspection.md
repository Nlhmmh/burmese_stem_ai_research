# Structured usability inspection

Detailed sections: [Execution and evidence capture](#how-codex-ran-the-tests-and-recorded-evidence), [Human review guide](#how-to-review-the-evidence-step-by-step), [Case register](#case-register), [Recorded issues](#recorded-usability-issues).

## Run and scope

RUN-B01-20261002-USABILITY-01, 2 October 2026. Root B01 production application, isolated MongoDB and controlled provider fixtures; no live model calls. There were 133 captures (131 main plus two navigation rechecks). Evidence E036–E038. This is structured technical inspection, not participant feedback or a full accessibility audit.

Desktop 1440 × 900 and simulated mobile 390 × 844, English/Burmese UI and light/dark themes formed eight configurations. Home, preferences, initial support and Stage 6B covered all eight. Later states covered selected combinations rather than every possible state/configuration pair. Keyboard, delayed loading, recovery, bounded choices and bilingual override were inspected.

## How Codex ran the tests and recorded evidence

Codex operated the terminal and Chrome browser controls. The application was inspected through real clicks, native keyboard actions and read-only DOM observations. No participant study was conducted, and the screenshots do not establish translation accuracy or learning.

- **Start the root application.** [run_inspection_server.mjs](raw/run_inspection_server.mjs) verified B01 production-file hashes and started the existing production build with a separate MongoDB database. It recorded source/build identity in [metadata.json](raw/RUN-B01-20261002-USABILITY-01/metadata.json). No source-copy checkout was created.
- **Prepare visible test states.** [seed_inspection_states.mjs](raw/seed_inspection_states.mjs) and [add_route_seeds.mjs](raw/add_route_seeds.mjs) inserted artificial legacy, round-1/2, completed, long-content, language and foreign-owner sessions. These database fixtures made states inspectable; they are not evidence that the browser created each state.
- **Control the provider only.** The [provider hook](raw/provider-hook.cjs) supplied saved initial outputs and synthetic adaptations/corrections through the [black-box hook](../black_box/raw/provider-hook.cjs). It added a 1,500 ms delay for loading checks. Twenty-nine intercepted requests and zero external model calls were recorded in the [provider log](raw/RUN-B01-20261002-USABILITY-01/provider.jsonl).
- **Inspect and capture.** Chrome controls were used across the eight recorded width/locale/theme configurations. Each capture saved a screenshot, DOM text and an [observation record](raw/RUN-B01-20261002-USABILITY-01/observations.jsonl) with an ID, state, dimensions, locale, theme, note and severity. Keyboard actions and focus were also captured. The DOM was not changed to force invalid options.
- **Keep corrections and rechecks separate.** [observation_corrections.jsonl](raw/RUN-B01-20261002-USABILITY-01/observation_corrections.jsonl) records changes to written observations without deleting original captures. Two later Back-navigation checks are in the [navigation addendum](raw/RUN-B01-20261002-USABILITY-01/navigation_addendum.jsonl). [Its verification](raw/RUN-B01-20261002-USABILITY-01/navigation_addendum_verification.json) checked that Back restored choices without adding a provider request or saved-state change.
- **Assemble the review records.** [finalize_records.mjs](raw/finalize_records.mjs) applied the explicit corrections to the [readable observation CSV](raw/RUN-B01-20261002-USABILITY-01/observations.csv), exported comparison records and redacted synthetic identity-cookie values from shareable text. [Verification](raw/RUN-B01-20261002-USABILITY-01/manifest_verification.json) counted 133 screenshots and DOM captures. Counts and hashes support traceability, not a usability Pass by themselves.
- **Format readable evidence.** The [converter](../convert_readable_evidence.mjs) groups observations, review-sheet entries, corrections, labelled provider records and issues by U1–U9. Only recorded criterion mappings and exact labels are used. Shared fixtures, database snapshots and unlabelled provider records remain in [the shared index](raw/readable/index.json). It does not perform a new browser inspection.

## How to review the evidence step by step

- **Choose U1–U9.** Read its action, conditions and expected result. Open its Readable logs link. `records.browserObservations` contains all captures assigned to that criterion, not only the table's screenshot examples. `records.reviewSheet` contains the readable CSV entries.
- **Check how the state was prepared.** Inspect [seed_inspection_states.mjs](raw/seed_inspection_states.mjs), [add_route_seeds.mjs](raw/add_route_seeds.mjs), [seeded_documents.json](raw/RUN-B01-20261002-USABILITY-01/seeded_documents.json), [ui_seeds.json](raw/RUN-B01-20261002-USABILITY-01/ui_seeds.json) and the provider hook. Confirm the learner, round, status, language and any injected error match the case conditions.
- **Open each selected screenshot and DOM file.** Their paths are in each observation's `record`, relative to the historical run folder. Compare the visible labels, support, navigation, error or next action. Check `viewport`, `locale`, `theme` and `keyboard_steps` in `reviewSheet`. A mobile viewport is not a physical-phone test.
- **For keyboard focus, read the trace.** Use [keyboard_modal_trace.json](raw/RUN-B01-20261002-USABILITY-01/keyboard_modal_trace.json) with the U5/U9 screenshots. Check where focus starts, where Tab moves and where focus ends after Escape.
- **For loading, Back or saved state, check more than the screen.** Read the provider log, [database snapshot](raw/RUN-B01-20261002-USABILITY-01/database_snapshot.json) and navigation verification. A `-L` filename alone does not prove that loading was captured.
- **Read corrections and issues.** Compare `browserObservations` with `observationCorrections`; originals have not been replaced. Read `recordedIssues` for severity, task effect, workaround and proposed fix. No fix was implemented by this inspection.
- **Check the rating rule and limitation.** Severity 1 is cosmetic; 2 means a difficulty with a workaround; 3 means blocked or seriously misleading behaviour. Partial also applies to missing planned coverage. The rating is an inspection judgement, not participant feedback.
